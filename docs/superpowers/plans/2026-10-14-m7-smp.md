# M7: Multicore (SMP) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Ownership:** Tasks 1 and 7 are Claude's (harness, review, docs). Tasks 2–6 are the **user's** (kernel core). An agent MUST NOT write the non-test parts of `sched.rs`, `task.rs`, `collections/` or `arch/` unless the user asks; it may explain and review.

**Goal:** Both cores run tasks from one global ready set. Two CPU-bound tasks finish in the time one takes alone; a `give()` on one core wakes a task on the other at once (not at the next tick); a task is never run by two cores, nor by one core before the other has saved its registers.

**Architecture:**
- **Global SMP, one big kernel lock.** One `Sched` for both cores. `with_sched` = mask this core's interrupts, then spin on `KLOCK` (an `AtomicBool`), then `set_core(core_id())`. Every scheduler question ("current task", "should switch") is about `self.core`.
- **Per-core state in `Sched`:** `current: [*mut Task; 2]`, `idle: [*mut Task; 2]`. Idle tasks are pinned to their core and never on a ready list.
- **`Task::on_cpu`:** set when a core picks the task, cleared in that core's next `switch` (after PendSV saved its registers). `highest_runnable` skips `on_cpu` tasks: a task woken by core 1 while core 0 is still switching it out stays where it is until core 0 is done.
- **Cross-core kick (SIO doorbell, IRQ 26).** After any change to the ready set: pend this core's PendSV if it should switch; ring the other core if a runnable task is *strictly* more urgent than what it runs. The doorbell handler re-checks under the lock and pends its own PendSV.
- **Time:** only core 0's SysTick ticks. It ends core 1's time slice too, by ringing it (`>=`, unlike the strict `>` of a cross-core wake).
- **Critical sections across cores:** masking stops only this core, so `critical-section` also takes a re-entrant cross-core lock (`CS_OWNER`). `CsEnter`/`CsExit` are handled before the kernel lock is taken; nothing logs while holding the kernel lock.
- **Boot:** the app spawns core 1 into `kernel::start_secondary` (HAL `Multicore`), before `kernel::start`. Core 1 waits for `STARTED`, repeats the per-core setup (`init_core`), and switches to its idle.
- **Test exit from either core:** probe-rs only watches core 0 for the semihosting `bkpt`. `kernel::exit` (test-hooks) on core 1 hands the exit code to core 0 through the doorbell.

**Spec:** `docs/superpowers/specs/2026-10-14-rtos-kernel-design.md` (milestone M7)

## Global Constraints

- Everything in the M0–M6 plans' Global Constraints still holds.
- Lock order: **mask, then lock**. Never take the critical-section lock while holding `KLOCK`; never log (defmt) inside `with_sched`.
- No SIO hardware spinlocks: RP2350 erratum E2 (writes to SIO above +0x180, the doorbells included, can release them). Atomics only.
- Binaries that don't call `Board::start_core1` run on core 0 alone, exactly as before.
- Board tests need the full `timeout -s INT 120`: after a semihosting exit, probe-rs takes ~70 s to reopen the probe (same on 556a97e, not an M7 effect).
- Verified on this board with a throwaway reference (2026-10-24):
  - 59 host tests. `m7_smp`: "one task 80 ms, two tasks 80 ms"; "cross-core wake-up: worst 16–23 us over 20 rounds"; "ping-pong: 40000 handoffs in 367 ms". 20/20 runs exit 0 once exits went through core 0.
  - All M1–M6 board tests pass. IRQ→task latency (`m3_sem`) 18 µs, up from 14 (lock + kick).
  - A panic in a privileged task on core 1 ends the run with exit 1 (3/3).
  - Mutants caught: `highest_runnable` ignores `on_cpu` → host test `task_woken_before_its_switch_out_is_not_picked_by_the_other_core` fails; no ring in `kick` → "worst 1004 us", assert fails; `with_sched` without `KLOCK` → scheduler corrupted, `m7_smp` panics; `request_exit` doing the `bkpt` on core 1 → panic logged, run never ends (124).
  - Found while building it: with `>=` for cross-core preemption, two equal-priority tasks made the cores ring each other forever ("two tasks 1227 ms" instead of 80). Hence `should_preempt` is strict.

```rust
pub(crate) on_cpu: bool;   // false in build/idle/for_test

// kernel/src/collections/list.rs
impl<L: Link> TaskList<L> {

// kernel/src/sched.rs
pub(crate) const CORES: usize = 2;
impl Sched {
    pub(crate) fn set_core(&mut self, core: usize);
    pub(crate) unsafe fn set_idle(&mut self, core: usize, t: *mut Task); // state Ready, not listed

    pub(crate) fn should_switch(&self) -> bool;                // = should_switch_on(self.core)
    pub(crate) fn should_switch_on(&self, core: usize) -> bool; // runnable prio >= current's
    pub(crate) fn should_preempt(&self, core: usize) -> bool;   // runnable prio >  current's
}
// `current()`, `switch()`, `sleep_current`, `block_current`, `kill_current`,
// the mutex paths: all on `self.current[self.core]`.

// kernel/src/arch/mod.rs
pub fn start_secondary() -> !;
#[cfg(feature = "test-hooks")] pub fn exit(success: bool) -> !;
pub(crate) fn core_id() -> usize;
pub(crate) fn kick(s: &mut Sched);
pub(crate) fn request_exit(reason: u32) -> !;

// kernel/src/arch/svc.rs
pub(crate) enum Sys { .., CsEnter, CsExit, Exit }   // Exit last
pub(crate) fn unprivileged_task() -> bool;
pub(crate) fn cs_release_if_owner(core: usize);

// kernel/src/lib.rs
pub use arch::{now, sleep, sleep_until, start, start_secondary, yield_now};
#[cfg(all(target_arch = "arm", feature = "test-hooks"))] pub use arch::exit;
```

RP2350 registers: SIO `CPUID 0xD000_0000`, `DOORBELL_OUT_SET 0xD000_0180`, `DOORBELL_IN_CLR 0xD000_018C`; `SIO_IRQ_BELL` = IRQ 26 (vector name `SIO_IRQ_BELL`); ACTLR `0xE000_E008` bit 29 (EXTEXCLALL); NVIC IPR byte `0xE000_E400 + n`, ISER0 `0xE000_E100`.

### Task 2 (User): the scheduler on two cores — `task.rs`, `collections/list.rs`, `sched.rs`

**Goal:** all 59 host tests pass.

1. `Task::on_cpu: bool`, false in `build` (and `idle`).
2. `TaskList::find(f)`: walk from `head` along `L::link` until `f(t)`.
3. `Sched`: `current: [*mut Task; CORES]`, `idle: [*mut Task; CORES]`, `core: usize`; replace every `self.current` with `self.current[self.core]`.
4. `set_core`, `set_idle` (store, mark Ready). `make_ready(t)` on an idle task: only mark it Ready, never push it.
5. `highest_runnable`: for each set bit of `bitmap` from the top, `find(|t| !(*t).on_cpu)`; the first hit wins. (`highest` goes away.)
6. `switch` on `self.core`: outgoing task → `on_cpu = false`, re-queue it if still `Running`; next = `highest_runnable` (then `remove` it, clear the bit if the list empties) or `idle[core]`; mark it `Running`, `on_cpu = true`, `current[core] = next`.
7. `should_switch_on(core)` (`>=`), `should_preempt(core)` (`>`), both false while `current[core]` is null; `should_switch()` = `should_switch_on(self.core)`.

**Hints**
- Why `on_cpu`, not just "is it Ready?": core 0's task blocks (state Blocked, PendSV pending but not run yet, registers *not saved*). Core 1 gives the semaphore: the task is Ready again. If core 1 now picked it, it would restore registers from a stale `sp`. `on_cpu` stays true until core 0's `switch` runs, i.e. after the save.
- Clearing `on_cpu` in `switch` is right because `switch` runs in PendSV *after* the context save.
- Idle off the ready lists: otherwise core 1 could pick idle0, whose stack core 0's first PendSV writes into (the first-switch PSP trick from M1).
- Why two predicates: the tick ends a time slice (`>=`: a peer of equal priority gets its turn). A wake-up only interrupts the other core for a strictly more urgent task. With `>=` there, each switch readies a task of equal priority for the other core, which switches, readies one back… a doorbell storm.

### Task 3 (User): the kernel lock and the per-core setup — `arch/mod.rs`

**Goal:** builds; with Tasks 4–6, `m7_smp` passes.

1. `SCHED` stays; `IDLE: [Option<Task>; CORES]`, `IDLE_STACK0`/`IDLE_STACK1` (`crate::stack!`, 128).
2. `KLOCK: AtomicBool` and `STARTED: AtomicBool`, both in `.kobj`.
3. `with_sched`: `interrupt::free`, then `compare_exchange_weak(false, true, Acquire, Relaxed)` spin, `s.set_core(core_id())`, run `f`, `KLOCK.store(false, Release)`.
4. `init_core()`, run by each core: PendSV/SysTick priorities, enable MemManage/BusFault/UsageFault, ACTLR.EXTEXCLALL, doorbell IRQ priority 0x80, `DOORBELL_IN_CLR = 0xFF`, enable IRQ 26 in ISER0, `mpu::init()`.
5. `start`: both idles with `set_idle`; `init_core()`; SysTick as before (core 0 only); PSP = idle0's `sp`; `STARTED.store(true, Release)`; `yield_now()`.
6. `start_secondary()`: spin until `STARTED` (Acquire); `init_core()`; PSP = idle1's `sp`; `yield_now()`.
7. `kick(s)`: `if s.should_switch() { set_pendsv }`, `if s.should_preempt(1 - core_id()) { ring_other_core() }`.
8. `SIO_IRQ_BELL`: clear the doorbells first, then `with_sched(|s| if s.should_switch() { set_pendsv })`.
9. `SysTick`: inside one `with_sched`: `tick()` → pendsv; `should_switch_on(1)` → ring.
10. `kernel_switch`: after `s.switch()`, `if s.should_preempt(1 - core_id()) { ring }` (the task just switched out may be what the other core should run).

**Hints**
- Mask, then lock. The other way round, SysTick can hit between "lock taken" and "masked", and spin forever on the lock its own core holds.
- EXTEXCLALL: the MPU regions are non-shareable, and LDREX/STREX on non-shareable memory only use the core-local monitor; another core's store would not break the reservation. The HAL sets this bit on the core it spawns, but not on core 0.
- Every core has its own NVIC, SCB, SysTick, MPU, PSP, BASEPRI: whatever core 0 configured, core 1 must configure again. A missed one shows as "core 1's tasks run privileged" or "faults go straight to HardFault on core 1".
- Clear the doorbell *before* deciding: a ring that arrives during the decision then raises a new interrupt instead of being cleared unseen.
- A ring is only a hint to re-check: by the time the handler runs, the reason may be gone. Decide again under the lock.
- Only one SysTick: two would advance `now` twice per ms.

### Task 4 (User): syscalls and critical sections on two cores — `arch/svc.rs`

**Goal:** `m7_smp` passes; `m5_fault`, `m6_mpu` still pass.

1. `CS_OWNER: AtomicU8` in `.kobj` (0 = free, else core + 1). `cs_lock(core) -> bool` (false if this core already holds it, else spin `compare_exchange_weak(0, me)`), `cs_unlock()`, `pub(crate) cs_release_if_owner(core)`.
2. Restore state: `VIA_SVC = 0x100`, `NESTED = 0x200` (lock was already ours: don't release).
   - Privileged `acquire`: read PRIMASK, `cpsid`, then `cs_lock`; state = enabled bit | `NESTED` if nested. `release`: unlock unless `NESTED`, re-enable if bit 0.
   - Unprivileged: `CsEnter` returns `old BASEPRI | NESTED?`; `release` passes `state & 0x2FF` to `CsExit`.
3. `svc_dispatch`: decode `Sys` first; handle `CsEnter` (BASEPRI 0x80, `cs_lock`) and `CsExit` (unlock unless `NESTED`, restore BASEPRI) **before** `with_sched`, and return.
4. Kill reasons: record them in an `enum Kill { BadNumber(u8), BadObject(u32), BadSlot(u32) }` inside the closure, `error!` after `with_sched` returns.
5. `finish`: pendsv if the caller is no longer Running, then `super::kick(s)` (replaces the `should_switch` check). `from_handler`: `super::kick(s)` too.

**Hints**
- Why the critical-section lock: defmt (and the HAL) use `critical-section` to guard shared state; masking interrupts on core 0 does nothing to core 1, so two cores logging at once would interleave RTT writes.
- Why re-entrant: a privileged handler can log while an outer section on the same core holds the lock (nested `acquire`), and must not deadlock with itself.
- Why `CsEnter` outside `with_sched`, and logging after: the dispatcher holds `KLOCK`; if it then logged, it would take `CS_OWNER` (order KLOCK → CS). A task logging takes `CS_OWNER`, and if it then made a syscall needing `KLOCK` (order CS → KLOCK), two cores could each hold one and wait for the other forever.
- Doorbell at priority 0x80 = SysTick's: a task's BASEPRI-0x80 critical section holds off both.

### Task 6 (User): ending a test run from either core — `arch/mod.rs`, `arch/svc.rs`

**Goal:** all board tests exit 0 with `TEST PASS`, including when the checker runs on core 1.

probe-rs only watches core 0: a semihosting `bkpt` on core 1 halts core 1 and nobody notices. So core 1 passes the exit code to core 0.

```rust
// arch/mod.rs
#[unsafe(link_section = ".kobj")]
static EXIT_REQ: AtomicU32 = AtomicU32::new(0);

/// Semihosting SYS_EXIT (REPORT_EXCEPTION) with `reason`; core 0 only.
fn semihost_exit(reason: u32) -> ! {
    unsafe { core::arch::asm!("bkpt #0xab", in("r0") 0x18u32, in("r1") reason, options(nostack)) };
    loop { cortex_m::asm::wfe(); }
}

pub(crate) fn request_exit(reason: u32) -> ! {
    if core_id() == 0 {
        semihost_exit(reason);
    }
    EXIT_REQ.store(reason, Ordering::Release);
    ring_other_core();
    cortex_m::interrupt::disable();
    loop { cortex_m::asm::wfe(); }
}

#[cfg(feature = "test-hooks")]
pub fn exit(success: bool) -> ! {
    let reason = if success { 0x2_0026 } else { 0x2_0023 }; // ApplicationExit / RunTimeErrorUnknown
    if svc::unprivileged_task() {
        svc::<{ Sys::Exit as u8 }>(reason, 0, 0, 0);
    }
    request_exit(reason)
}
```

- `SIO_IRQ_BELL`, right after clearing the doorbells: `if EXIT_REQ != 0 { semihost_exit(r) }`.
- `with_sched`'s spin loop: same check when `core_id() == 0` (core 1 may have panicked holding `KLOCK`).
- `svc.rs`: `Sys::Exit` (last in the enum and the decode array). Before `with_sched`: `Ok(Sys::Exit) if cfg!(feature = "test-hooks") => super::request_exit(*frame)`. Inside, without test-hooks: kill the caller as a bad number.
